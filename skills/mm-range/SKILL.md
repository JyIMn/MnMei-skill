# MM-range：跨领域组队

`MM-range` 是对外展示名，运行时 skill id 是 `mm-range`。

来源：Felix Rieseberg《How to be more ambitious: a tutorial for humans with models》（2026-10）里「range」一节。核心判断：一份交付物的质量上限，取决于有没有把**做这件事最专业的那些领域**都请进来；而请进来的方式是让它们**做事**，不是让模型换个口吻说话。

和相邻 skill 的分工：`mm-deepen` 在一个领域里做到专家级；`mm-range` 把多个领域拉进来。它也不是圆桌辩论——辩论是探索观点，`mm-range` 要的是做出东西。

## 先判断值不值得

只用于做错代价高、会被别人拿去用或做决定的交付物。一次性的小事直说「这件不值得组队」，然后正常做。

## 五步

### 1. 名词换动词
把交付物从「一份 X」改写成一句动词句：**让谁、在什么条件下、相信/做出什么**。
- 例：季度复盘不是「一份 PPT」，而是「让很忙的人在 30 分钟里相信一个因果故事，并在不确定中做决定」。
- 例：报价方案不是「一份报价单」，而是「让老板在一次会上相信这笔钱换得回来，并且敢拍板」。
- 再把这句拆成 3–5 个子动作（证明因果、讲清故事、让人当场决定、扛住质疑……）。动词句要用户点头，后面全部建在它上面。

### 2. 每个子动作找最擅长它的领域
为每个子动作问：**哪个行当的人每天以做这件事为生？** 选 3–6 个角色，至少 1 个红队。
- 写清每个角色**做什么动作、交出什么东西**，不写人设和性格。
  - 好：「做空研究员：找出这份方案里最站不住的三个数字，各自用原始数据重算。」
  - 坏：「做空研究员：犀利、怀疑一切的视角。」
- 优先跨行：除了本行当，找一个看似无关但正好以这个动作为生的行当（讲故事 → 记者/纪录片剪辑；让人决定 → 谈判/销售；扛质疑 → 尽调律师、法务会计）。
- 每个角色都必须能改变最终产物；改变不了的删掉。人数不是越多越好。

**先把动词句 + 阵容表给用户看，点头再开始做**（阵容定错了，后面全白做）。阵容表格式：

| 角色 | 负责的子动作 | 具体做什么 | 交出什么 | 用哪份原始素材 |
|---|---|---|---|---|

### 3. 派活：做事，不演戏
- 子 agent 是让这件事更容易的手段，不是必须。角色多、各自要读大量素材或互不依赖时，可以考虑每个角色派一个子 agent 并行跑；角色少、素材少时，在主线程做就行。派子 agent 时给它：动词句、它的子动作、原始素材路径、要交出的具体东西、完成标准。
- 指令写成「去做 ___ 会做的研究/计算/改稿」，不写「以 ___ 的口吻评价」。角色扮演只会让输出变怪，不会变好。
- 在主线程做时，按角色顺序逐个做，每段开头写明当前在做哪个动作。
- 红队最后上：拿着合成后的成品去攻击，而不是攻击草稿。

### 4. 合成
主线程把各角色交回的东西合成为最终产物：
- 角色之间结论冲突：并列写出各自的证据，影响结论的交用户裁决，不自己和稀泥。
- 红队提出的每个问题逐条处理：修了（改了哪）／不修（理由）。
- 最终产物服务于第 1 步的动词句，不是各角色意见的拼盘。

### 5. 外部裁判
说清除了用户和模型之外，什么能判定这份东西成了：真实接收者的反应、数据回执、能复跑的计算、独立来源核对。给不出就写「目前没有外部裁判，只能当假设」，并提一个最小验证动作（比如先发给一个真实接收者看反应）。

## 输出格式

第一轮只出到阵容表：

```
**动词句**：让 ___ 在 ___ 下 相信/做出 ___
子动作：1. … 2. … 3. …

**阵容**
| 角色 | 子动作 | 具体做什么 | 交出什么 | 原始素材 |

要不要按这个阵容开始派活？
```

用户点头后执行第 3–5 步，最终交付：成品 + 红队问题处理表 + 外部裁判建议。

## 原则

- 不编造角色会用的方法、数据或出处；拿不准就标注。
- 原始素材先在当前环境里找（本地文件、云文档、会议录音、平台后台），找不到写清缺什么。
- 按某个框架推断时注明「按 ___ 框架」。
